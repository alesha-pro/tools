# Engine

## Set up

```bash
bash scripts/new-project.sh ~/videos/my-song
```

This clones [mexicat/pdoom-video](https://github.com/mexicat/pdoom-video) (MIT) at the commit the patch is made
against, applies `assets/engine.patch`, copies `assets/lib/kit.ts`, `assets/lib/brand.ts`,
`assets/scenes/credits.ts`, fetches the display fonts (Google Fonts, OFL/Apache), copies the pop fonts, links
`app/public/art -> <project>/assets` and runs `bun install`. Requirements: bun, Google Chrome, ffmpeg with
libx264; the analysis tools need uv and Python.

Layout after setup:

```
<project>/
  BRIEF.md            the brief (intake.md)
  styleframes/        style exploration
  assets/<world>/     generated stills, served at art/<world>/<name>.png
  renders/            outputs
  engine/
    audio/            the song (replace pdoom.mp3; keep one file, wav preferred)
    data/             lyrics.json + audio.json (generated by analysis/)
    analysis/         alignment + beat analysis (Python, uv)
    app/src/engine/   renderer core (patched)
    app/src/lib/      kit.ts (world kit), brand.ts (handles, watermark)
    app/src/scenes/   one module per section; the upstream pdoom scenes are examples, delete when done
    app/src/timeline.ts  the edit
    app/scripts/render.ts  offline renderer
```

The upstream scenes (`open`, `loss`, `prompt` …) still compile and render after the patch; they are good
reading for scene technique. Replace `timeline.ts` with your own edit and delete the scenes you do not use.

## Timing data

Two files drive everything:

- `data/lyrics.json`: lines → words, each word `{ w, start, end, conf, syl? }`. `syl` holds syllable or part
  times for words sung in pieces (B-three-hundred, A-I, acronyms). The engine applies a display lead
  (`LYRIC_LEAD`, default 0.13 s): a word shown exactly on its acoustic onset reads late.
- `data/audio.json`: `duration`, `bpm`, `beats[]`, `downbeats[]`, `sections[]`, 100 fps envelopes
  (rms, low, mid, high, vocal, drums, bass, other) and onsets (kick, snare, hat, vocal).

Produce them with the upstream analysis tools (Demucs stems, CTC forced alignment with two acoustic models,
Whisper cross-check, beat/downbeat/section analysis). They are written for the upstream song; adapt:

| File | Change for a new song |
|---|---|
| `lyrics/lyrics.src.js` | the lyric lines (approximate line times are enough) |
| `analysis/common.py` | `AUDIO` path, stems folder name; `STEM_OFFSET_SAMPLES = 0` for a wav (the mp3 value compensates the LAME encoder delay) |
| `analysis/ctcalign.py` | `N_FRAMES = duration / 0.02` |
| `analysis/whisper_run.py` | the prompt: the song's unusual words (brand names, acronyms) |
| `analysis/pron.py` | phonetic spellings for acronyms and odd words (`"A-I": "ay i"`, `"Qwen": "kwen"`) |
| `analysis/align.py` | clear the upstream `FIX` anchors; add your own after checking the QA plots |
| `analysis/analyze.py` | the section map in bars; the beat tracker (see below) |

`assets/analysis-example.patch` is the full set of these edits from the example song. Two parts are worth
reusing as they are:

- **Variable-tempo beat tracking.** Generated songs (Suno) drift: the example went from ~133 to ~137.7 BPM.
  The upstream tracker assumes a constant tempo. `track_beats()` in the patch is a phase-locked loop on a
  drum + mix onset envelope with a Gaussian prior around each predicted beat, then a local quadratic smoothing.
- **Chorus consensus.** Repeated choruses are near copies; the patch replaces outlier word positions with the
  consensus bar position across choruses. Buried words get fixed this way.

Check the result before designing anything: render the `synctest` scene over a chorus (every word pops on its
start) and watch it with sound. Fix alignment first; nothing downstream can hide a late word.

## Scene API (short)

A scene is a class with `render(f: Frame, out: RenderTarget)` returning optional post overrides.

- `f.t` song time, `f.lt` time since the entry start, `f.beat`/`f.bar` continuous indices, `f.a` audio sample
  (envelopes and onset hits at t).
- `this.ctx`: `renderer`, `comp` (compositor), `lyrics`, `audio`, `params` (from the timeline entry),
  `start`, `end`.
- `init()` async, once: load art (`await loadArt([...])`), find lines, precompute stroke text.
- `prepare(t0, t1)` async, optional (added by the patch): preload what frames in [t0, t1] need. The export awaits
  it per frame; the preview calls it ahead without waiting.
- Drawing: a `Layer2D` (Canvas2D at the output scale, logical 1920x1080 coordinates), `L.clear()`,
  draw, `comp.draw(renderer, L.upload(), out)`. `clearRT(renderer, out, LIN.paper)` for the background.
  `FSPass(glsl, uniforms)` for full-screen shader passes (sketch looks, colour wipes); `GLSL_COMMON` provides
  `hash12`, `sat`, colour constants.
- Return `{ shake: [x, y], zoom, ca, grain, flash, ... }` to drive the post pass (camera shake, punch zoom,
  chromatic split, grain, white flash).
- Lyrics: `lyrics.find(text)` all lines containing text, `lyrics.get(text, nth)`, `line.words[i].start`,
  `word.syl`. Audio: `audio.beats`, `audio.downbeats`, `audio.beatAt(t)`, `audio.timeOfBeat(i)`.

The kit (`app/src/lib/kit.ts`) adds motion and three example world toolkits; see
[edit-and-motion.md](edit-and-motion.md).

## What the patch adds to the engine

| Feature | Where |
|---|---|
| `Scene.prepare(t0, t1)` preload hook, awaited by export, `still()` async | `scene.ts`, `engine.ts`, `main.ts` |
| Fonts with weight ranges (variable Inter, Caveat), `fontW(family, px, weight)`, kit fonts registered | `type.ts` |
| Pop palette tokens (`HEX.pink`, `cobalt`, `lemon`, `mint`, `lilac`, `ink`) and GLSL constants | `palette.ts`, `glsl/common.ts` |
| HUD overlay hook (`engine.hud.overlay`) drawn above everything, not affected by shake or zoom: the watermark | `hud.ts`, `post.ts`, `main.ts` |
| Timeline may run past the song (end card); audio padded with silence on export | `engine.ts`, `render.ts` |
| `CALM` energy knob (`?calm=0.65`, `--calm`): scales hits, springs, whip roll, cut flashes | `util.ts`, `engine.ts`, kit |
| Renderer flags: `RENDER_ANGLE=vulkan` (Linux GPU), `RENDER_CPU=1` (SwiftShader), `CHROME_PATH`, `--tune none`, `--calm` | `render.ts` |
| Lyric helpers used by the kit | `lyrics.ts` |

Palette and fonts are the example's; change the tokens for your look, keep the names or update the kit.

## Preview

```bash
cd engine/app && bunx vite          # http://localhost:5173, ?t=<seconds> to start somewhere
```

Space play/pause, arrows seek, `,` `.` step a frame, `[` `]` previous/next scene, `l` loop the scene.
