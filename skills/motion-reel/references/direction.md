# Direction by mode

## Showreel
Choose one visual thesis (for example folded paper becoming typography), then vary technique within it. A 15-second reel usually supports 5–8 short beats: strongest opening, geometric transformation, typography, depth/camera, a surprising payoff, resolved ending. Design a connecting shape, color or rhythm rather than unrelated tricks. The generic “show your skills” prompt is useful only to test the runtime.

## Product film
Use real logo, fonts, screenshots and verified facts. A useful arc is problem → product action → outcome → evidence → CTA, with fewer steps when duration demands it. A cursor must point at the control responsible for the visible result. Never substitute a made-up success metric. Capture sufficient real states to animate the story. Reconstructed UI is acceptable only for an explicitly authorized concept; distinguish it from a recording of the actual product.

## Continuous UI morph
List states as a table: time/frame, triggering action, container geometry, content, cursor position, sound. Keep one visual container through button, field, loader, result and dashboard states. Derive width, height, radius, fill and position from tracks. Stagger content visibility so outgoing/incoming text cannot collide. Give leading and trailing indicator edges different responses where useful. Reserve time for the return to the initial state; check cursor velocity and audio tail at the seam.

At 120 BPM, one beat is 0.5 s; eight 4/4 bars last 16 s, not 15 s. Adapt the grid to the requested duration rather than silently changing the brief. Not every beat needs a cut: cursor, highlight, type reveal or camera response can carry it.

## Narrative / long film
Start with logline and end feeling. Map acts and visual payoffs, then assign chapter frame ranges. Keep character proportions, palette, costumes and expressions in a bible. Make an animatic before detailed rigs. If generated motion is used as a tracing reference, record its provenance, budget and intended role; do not claim the result is purely procedural when raster footage remains visible. External generation is optional, not a dependency.

Keep a resume note with completed shots, render commands, asset locations, known defects and next action. If a separately authorized multi-agent workflow is used, define scene API, global frame ranges, coordinate system, fonts, palette, audio contract and file ownership first.

## Brief fields to fill with concrete choices
- Subject, audience, one takeaway, exact copy and call to action.
- Duration, fps, requested aspect ratios, loop or resolved ending.
- References: observable properties to borrow, elements to exclude.
- Palette, typography, texture, camera and motion weight.
- Assets and source URLs; unavailable facts/assets explicitly marked.
- Shot table with exclusive end frames and audio cues.
- Music source and handling, voice if requested, provider budget if any.
- Output paths and observable acceptance criteria.

Do not require the user to fill a questionnaire when the brief already answers these. Draft sensible creative choices; ask for missing facts only.
